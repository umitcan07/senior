# E7.6 — PanPhon feature-weighted phone diff: feasibility report (issue #57)

**Status:** feasibility POC complete. **Verdict: GREEN — go**, with one important scoping nuance
(feature distance fixes *alignment*; *severity/reporting* needs a curated overlay). No production
code was changed; this report + a dev-only POC (`mod/dev/poc_feature_diff.py`) are the deliverable.

Date: 2026-06-07. Author: feasibility study for the E7 frontend epic (defense 2026-06-13).

## 1. Question

`mod/phone_diff.py` aligns the learner's POWSM phone sequence to a reference using a **binary**
equal/not-equal Levenshtein (`substitute=2`, `insert=delete=1`). Issue #57 comment #2 reports that
articulatorily-close phones can't align as cheap substitutions, so the traceback picks misleading
alignments (`l↔ɫ`, `ɑ̃↔ɔ̃`, `ɛ̃↔ɪ̃`, `ə↔ɜ˞` rendered as hard subs of unrelated phones). Does
replacing the substitution cost with a **PanPhon articulatory-feature distance**:
(a) work at all on POWSM's real token inventory, (b) actually improve the diff, (c) need a curated
Turkish-L1 override?

## 2. Method

POC: `mod/dev/poc_feature_diff.py` (dev-only, not wired in). It uses PanPhon's `FeatureTable`
per-phone vectors + our own Hamming distance — **not** PanPhon's string-level `Distance` (which
runs its own whole-sequence alignment and would replace our aligner, losing positions / ins-del /
GOP). A generic Wagner-Fischer mirrors `phone_diff._align` exactly but takes a pluggable
substitution cost; with the binary cost it is **verified bit-identical to production `phone_diff`
on 75/75 learner clips (0 mismatches)**, so the comparison is faithful.

Data (all committed under `data/`):
- **Native tier (CPU only):** 100 reference goldens (`data/references/*/ref_*.expected.json`),
  4 speakers × 25 sentences. Cross-speaker same-sentence diffs = a clean upper bound (both correct).
- **Learner tier (dev worker, POWSM):** 75 Turkish-L1 clips (`erem`, `omer`, `umit` × 25), each
  free-aligned with the **active LoRA fine-tuned model** (`adapter=mod/assessment/adapter`); the
  matching `genam_katherine` reference clip was re-aligned with the *same* model so the comparison
  isn't confounded by the baseline model that produced the committed goldens.

Feature cost used for headline numbers: `sub_cost = 2 · (differing_features / 24)`; "close" = Δ≤3
differing features. Reproduce: `python -X utf8 mod/dev/poc_feature_diff.py` (Tier 1) and, in the
worker, `python3 /worker/dev/poc_feature_diff.py --emit-learner` (Tier 2). Caches in `mod/dev/poc_cache/`.

## 3. Findings

### 3.1 Coverage gate — PASS (100%)
PanPhon vectorizes **every** POWSM token observed, to exactly one segment:

| Inventory | Unique tokens | Occurrences | Covered |
|---|---|---|---|
| Native goldens | 48 | 3 815 | **48/48 = 100%** |
| Learner + live reference | 72 | 5 566 | **72/72 = 100%** |

POWSM emits *decomposed* combining forms (`l̴`, `ə˞`, `ɜ˞`, nasalized `ɛ̃ ɪ̃ ɑ̃ ʊ̃ æ̃`, aspirated
`kʰ tʰ pʰ`) which PanPhon's NFD path covers natively. The fine-tuned model adds a long tail of
allophonic detail on learner audio — palatalized `bʲ cʰ mʲ fʲ vʲ dʲ pʲ lʲ`, dental `d̪ t̪`,
breathy `o̤ b̤ ṳ`, affricate `t͡ʃ` (with U+0361 tie bar), `ʎ ɲ ɐ ɒ ɟ c r bˠ` — **all covered**.
The `NORM_MAP` (3 precomposed entries `ɫ→l̴`, `ɝ→ɜ˞`, `ɚ→ə˞`) was **not needed** for any observed
token; it is a forward safety net. → The issue's premise of "~40 English phones" is wrong (real
inventory is 72+ with pervasive diacritics), but that is exactly why a feature metric is needed,
and PanPhon handles it completely.

### 3.2 The diff bug is real and feature weighting fixes it

**Native-vs-native upper bound** (150 same-sentence pairs, both speakers correct → any sub is by
definition a close near-miss or transcription noise): binary flags **145** hard substitutions;
under feature distance **83%** of them are articulatorily close (Δ≤3) — e.g. `ə→ɪ̃` (nasalization),
`k→kʰ` (aspiration), `b→p` (voicing), `i→ɪ̃`. Binary scores all of these as full errors between
two *native* speakers.

**Real learner data** (75 Turkish-L1 clips):

| | substitutions | insertions | deletions | total ops |
|---|---|---|---|---|
| binary (production) | 706 | 138 | 146 | 990 |
| feature-weighted | 763 | 108 | 116 | 987 |

- **Alignment changes on 50/75 clips (67%).**
- **60 spurious insertion+deletion pairs (284→224) collapse into correctly-localized substitutions.**
  Canonical case (real, `erem ref_004`): reference `…ɡ ə˞ …`, learner said `…ɡ ə ɹ…`.
  Binary: `ins(ə) · sub(ə˞→ɹ)` (two errors, mislocated). Feature: `sub(ə˞→ə) · ins(ɹ)` — the schwa
  correctly matches the rhotic-schwa target (Δ small), and the extra `ɹ` is a clean insertion.
- 79% of binary's substitutions (558/706) are feature-close; 205 are genuinely different (Δ>3).

### 3.3 Cost behaves correctly (self-tests)
identical → 0; diacritic-only (`ɛ/ɛ̃`, `l/ɫ`, `s/z`, `ɪ/i`) → Δ1, cost 0.083; `θ/s` → Δ2, 0.167;
`w/v` → Δ7, 0.583; `p/i` → Δ9, 0.75. Cost scaling is robust: synthetic Turkish epenthesis
(`speak` [s p i k] → [s ɨ p i k]) stays a clean **insertion** and a denasalized close pair stays a
single **substitution** for every scale ∈ {1.0, 1.5, 2.0, 3.0}. Recommended scale **2.0** (keeps the
max substitution cost at the current ceiling of 2, so ins/del balance is unchanged for far phones).

### 3.4 Severity model — decided from data: HYBRID
Pure feature distance is the right signal for **alignment cost**, but it is **insufficient for
pedagogical severity**. Of 13 core §4 Turkish-L1 contrasts, **10 are feature-close (Δ≤3)** and a
pure-distance rule would mislabel them "minor":

| Feature-close (Δ≤3) — would be wrongly downplayed | Feature-far (Δ>3) — flagged anyway |
|---|---|
| `θ→t/s`, `ð→d/z` (Δ2); `æ→a` `ɪ→i` `ʌ→a` (Δ1); `æ→ɛ` `ə→a` `ʊ→u` (Δ2) | `w→v` (Δ7); `ŋ→n` (Δ5); `ɹ→ɾ` (Δ5) |

A stop replacing a fricative differs in few *features* yet is highly salient to a listener and is a
textbook L1 error. → Use feature distance for the **alignment cost and a generic "close/minor"
hint**, but layer a **curated §4 (expected, actual) table** that overrides severity + hint text for
known-critical contrasts. This matches the issue's Tier-1 intent, now justified by evidence.

## 4. Critical caveats (honest limitations)

- **No phone-level ground truth.** Both sides are POWSM transcriptions; neither is hand-verified.
  "Improvement" = *more linguistically-plausible, better-localized alignment*, evidenced by the
  native-vs-native upper bound (where subs are definitionally non-errors) and qualitative learner
  cases. We **cannot** claim a PER-accuracy gain without labeled data — and should not, in the writeup.
- **"Close" (alignment) ≠ "ignorable" (reporting).** Conflating them would hide `θ→s`. Keep the two
  concepts separate in the API/UI (see §5).
- **Fine-tuned model emits fine allophony** (palatalization, dentalization, breathy voice). Feature
  distance absorbs these as near-misses — good — but it means many raw "errors" are transcription
  artifacts, an argument for GOP-gating (#20/#21) + the severity overlay, not for the raw diff.
- **Ternary features:** our Hamming treats `0` as a third value; PanPhon's own `feature_edit_distance`
  has special 0-handling. For coarse severity buckets this is immaterial; a 0-aware or
  `weighted_feature_edit_distance` variant is a possible refinement, not a blocker.
- **PanPhon feature count:** 24 named features incl. `hitone`/`hireg` (0 for all English segmentals →
  22 effectively distinguish). The issue's "/24" is fine; just don't quote "/24 differing" as if all
  24 ever vary.

## 5. Recommendation (implementation deferred to a follow-up PR)

**Go.** The eventual change is small and low-risk:
1. `panphon` → `mod/assessment/requirements.txt`; rebuild worker (adds ~a few MB + its IPA CSV; pure
   CPU, no latency concern — cost is a memoizable pure function of the phone pair).
2. New `mod/phone_features.py`: `FeatureTable` singleton + `NORM_MAP` + cached `feature_sub_cost(a,b)`
   (= `2·ΔfeatHamming/24`, fall back to 2 for any future uncovered token, and **log** it).
3. Inject that cost into `mod/phone_diff.py:_align` (the binary `==`/`substitute=2` at lines 53/58).
   Keep the `{errors, alignment, per}` contract, positions, ins/del semantics, and GOP linkage in
   `mod/assessment/assess.py` **unchanged**. Add `mod/tests/` unit tests (identical→0, diacritic→tiny,
   unrelated→~2) + a golden-regression guard (`verify.py batch --check`).
4. **Separately** (severity/hint layer, its own issue slice): a curated `doc/phone_hints.json` keyed
   on §4 (expected, actual) pairs that sets severity + plain-language hint, overriding the generic
   feature-distance bucket; carry a `severity`/`hint` field through `runpod-schemas.ts` → a
   `phoneme_errors` migration → webhook → `diff-viewer.tsx`. Gate coaching on GOP (#20/#21).

**Blast radius of the core fix:** `mod/phone_diff.py` + new `mod/phone_features.py` +
`requirements.txt` + worker rebuild. No schema/API/UI change until the hint layer. Must preserve:
`▁` stripping, 40 ms stride, `sub|ins|del` contract, GOP/entropy/uncertain fields.
